# Process, Case Studies, Pricing & Client Strategy

## Design process
- Start with user intent, not aesthetics: map each intent (search vs browse) to functionality; fonts/colors change aesthetics, not function.
- Content-first: (1) choose what content shows at each level (list = scannable essentials; details one click deeper); (2) structure for imperfect content — long names, bright images, empty states. No lorem ipsum, ever.
- Order: sketch flows (paper boxes: check for missing search/skip/back/states) → wireframe (fix layout variety HERE — a boring wireframe cascades) → test on a few people → hi-fi.
- Good design ≠ interesting design; captivation is a separate deliberate pass: layout variety → imagery → scale → depth → background → motion.
- Product design > UI design: (1) design ALL states — empty, loading, success, error; (2) design flows, not screens — how did they get here, what next (create → immediately prompt the next step with skip); (3) design system = decisions you stick to, not hundreds of components; semantic consistency (primary color never on the destructive button) lets users act without reading.
- UI = flavor (same layout, different feel); UX = journey decisions (verification blocking vs gentle reminder; team-vs-solo forks). Neither fork is "wrong" — but decide deliberately.
- Design systems: the rule-defining process matters more than the artifact; scale weight to team size; break the system only with intention.
- Collect inspiration from 4–6 competitors first; explicitly note what to copy and what to reject. Moodboard before designing — never start from a sliver of an idea.
- Diagnose before redesigning: list specific flaws per section, in writing.
- View at true size on the target device; browser chrome eats ~80px+ of height. Iterate visibly — good sections go through 4+ arrangements; don't ship attempt #1.
- Estimation law ×2: things take longer than you think; your skills are worth more than you think.
- Fix order for max ROI: layout > color > icons > effects.
- Learning loop: train the eye (annotated swipe file of ~20 sections) → clone pixel-for-pixel (forces noticing gaps/heights/padding) → restyle one layout twice + fork a UX flow.

## AI / vibe-coding rules
- AI handles logic and features when told explicitly; NEVER let it choose colors, layout, or icons.
- Its tells: emojis as icons, gradient letter-avatars, repeated KPI blocks, dead decorative cards, no images anywhere, bright clashing hues.
- Prompt recipe: say "design" explicitly; request HTML+CSS; state purpose; name required elements; demand an icon library (or you get emojis). Clean real-product screenshots as references work; busy Dribbble shots fail.
- Leave micro-tweaks for manual polish. Cleanup list for AI output: fonts, alignment, color, semantic color reuse, vague statuses, sidebar alignment.

## UX case study (8 steps)
1. Problem statement + solution snapshot at the TOP (never bury the outcome). Research-backed, even a simple form survey.
2. Presentation is half the content: images and GIFs every couple of paragraphs; annotated, titled, labeled data viz.
3. Personas: data-backed only, goals + frustrations relevant to the problem, no bikeshedding.
4. Color-coded user flows; small project + high polish beats big project.
5. Show low-fi wireframes, even messy — they demonstrate process.
6. Final designs LARGE with explanation alongside.
7. Reflection: what you'd improve, difficulties, sample limitations — admitting flaws reads senior.
8. Narrate as a story; readable in 10–15 min; intriguing chapter titles, not "Research"/"Solution".
- Client-facing mini case study: services → problem → solution → numbers. "Undeniable results are the single best sales pitch."

## Portfolio
- Headshot or video above the fold; concise intro (name + what you do); 2–3 pages max; large bright imagery (visitors see before they read); case studies readable from images alone, ending with "what I learned"; genuine about page; inject personality.
- Hiring-yourself test: would YOU hire you off this? If not a definite yes, keep working.
- With no clients: niche (passion + sellable) → briefs from generators, expanded by AI → 2–3 full case studies or 3–4 interface pieces. Personal site > Notion > Dribbble/Behance.
- Don't build the portfolio while still learning — taste shifts massively in 1–2 months.

## Pricing (US-market anchors; location-adjust)
- Hourly: $20–30 (1–2 yrs) → $35–50 (a few clients in) → $60–100. Hourly misaligns incentives — graduate off it.
- Project: break-even = hours × rate (include meetings + revisions), then ×1–2 by client quality (dream client ×1, average ×1.5, dreadful ×2).
- Value-based (the holy grail): 5–10% of the quantifiable revenue lift; needs a measurable revenue link, else fall back to project pricing.
- Sell problem-solving, not websites: niche on the problem ("large catalogs with organization issues"), not just the industry.
- Upsells that solve the core problem: CRO for high-traffic sites (marginal conversion beats more traffic), SEO, content, retainers.
- Offer design + build (one point of contact) and keep view-only analytics access to prove before/after impact.
- Clients judge UI; results come from UX. Aesthetic-usability effect is real — aim for both.
- Design for the end user, not the client who pays.
